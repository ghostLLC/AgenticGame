# Gameplay v2 据点争夺模式规格

## 目标

在既有歼灭决斗之外提供第一种目标驱动模式，让机动、路线、视野和区域控制共同影响胜负，而不是所有比赛都只靠击毁对手结束。

## 官方规则

- 模式 ID：`capture`；展示名：据点争夺。
- 胜利条件：连续占领目标区域 30 tick，或直接歼灭对方。
- `frontier-v2@2.1.0` 在地图中央提供一个 `central-zone`，区域内全部格子可通行。
- 只有一支存活队伍处于区域内时，每 tick 增加 1 点占领进度。
- 双方同时进入时区域进入争夺状态，当前连续进度重置；争夺期间双方均不增长。
- 正在占领的单位离开或被摧毁时，连续进度重置。
- 达到 30 点后立即以 `captured` 原因结束比赛；若先发生歼灭，则以 `destroyed` 结束。
- ruleset 2.1.0 到时存在单方有效占领进度才判定该方获胜，否则平局；历史 2.0.0 的原始剩余 HP 判定保留。

首期采用“连续占领”而非可累积点数，理由是规则易理解、回放因果清晰，并能直接奖励守住区域的能力。命中导致减速、受击掉点、多单位加速占领等规则留给后续平衡迭代。

## Bot 可见信息

`createTank(ctx)` 在开局获得公开的 `captureZones`；每个 `BattleViewV2` 获得当前 `objective`：

```ts
{
  zoneId: string;
  capturingTeamId: string | null;
  progress: number;
  required: number;
  contested: boolean;
}
```

区域位置和进度属于公开比赛目标，不受战争迷雾隐藏；敌方坦克与炮弹仍遵守视野规则。

## 回放事件

- `capture-progress`：单方占领增长，包含 team、当前进度和目标进度。
- `capture-contested`：双方同时在区内，仅在进入争夺状态时产生。
- `capture-reset`：占领者离开、被迫退出或争夺导致连续进度清零。
- `match-ended`：占领完成时 `reason=captured`。

Replay Studio 默认只把开始占领、每 10 点进度、争夺、重置和完成占领提升为关键时刻，避免逐 tick 事件淹没玩家。

## 验收证据

- 引擎单测覆盖连续占领胜利、争夺阻止进度和离开重置。
- 真实 worker 沙盒比赛在 30 tick 完成占领，Bundle 含 30 个进度事件、31 个含开局状态的检查点，并通过完整性校验。
- 两个 Bot 都能在初始化上下文读取同一公开占领区域。
- Replay Studio 投影将占领事件转换为玩家可读的关键时刻。
