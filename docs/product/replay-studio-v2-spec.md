# Replay Studio v2：持久化与界面投影规格

## 用户价值

比赛结束后，玩家应当能可靠地找到历史比赛、确认回放没有损坏、快速理解胜负原因，并从任意已保存回合继续查看战况。默认界面不展示源码、哈希或内部事件结构；这些信息只属于验证与高级诊断层。

## 本阶段范围

- `ReplayRepositoryV2` 按完整 `bundleHash` 保存不可变 MatchBundleV2 文件。
- 保存采用独占锁、临时文件、文件同步与同目录原子重命名；相同比赛包重复保存不产生副本。
- 真正加载/打开/导出始终完整校验 MatchBundleV2；列表使用最多 2,000 条经过验证的摘要缓存，并根据文件身份/修改信息失效。损坏项逐条隔离，健康项继续可用。
- `runMatchV2` 在生成完整比赛包后通过 `onBundle` 接入持久化，不需要另造简化比赛路径。
- 每场正常比赛包含 tick 0 初始检查点，Replay Studio 可以从开局定位。
- `createReplayStudioViewV2` 生成玩家侧摘要：模式、地图、双方配置、结果与关键时刻；不包含 Bot 源码或完整哈希。
- `seekReplayCheckpointV2` 返回目标回合或之前最近的已验证状态检查点。

## 数据目录

```text
<replay-root>/
├─ <bundleHash>.json
└─ .save.lock  # 仅在写入期间存在
```

未知 `.json` 文件名、非法哈希、损坏比赛包都不会被静默忽略。此约束避免 Replay Studio 在部分数据损坏时给玩家展示看似正常但不可验证的历史。

## 玩家侧信息层级

默认层：双方名称、车辆、武器、胜负、回合数、命中/摧毁/异常/比赛结束等关键时刻。

高级层：随机种子、最大回合、引擎版本。源码、完整哈希、原始日志仍保留在 MatchBundleV2 中，但不进入默认投影。

## 验收

- 真实 `runMatchV2` 输出可直接落盘、加载和列出。
- 重复保存幂等，篡改后加载与列表均失败。
- 路径穿越在文件系统访问前被拒绝。
- tick 0 与后续回合均可定位到已验证检查点。
- 玩家侧投影不包含源码或 64 位哈希。
