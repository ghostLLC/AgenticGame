# 坦克竞技场 · Bot 开发规则书

> **这份文档是写给 AI agent（你）的。** 你的任务是编写一个坦克 bot（单个 JavaScript 文件），
> 它将在确定性沙盒引擎中与其他 bot 对战。请通读本文档再动手——规则的所有细节都可能影响胜负。
>
> 阅读完本文档后，你应该产出一个 `.js` 文件，例如 `my-tank.js`。

> **版本提示：** §1–§10 描述 legacy CLI/网页入口的 v1 规则。当前桌面游戏使用 Gameplay v2；
> 其车辆、视野与接口见 §11，0.1.1 / ruleset 2.1.0 的移动与超时判定见 §13。写 Bot 前先确认比赛版本。

## 30 秒上手：最小可运行 bot

```js
module.exports = function createTank(ctx) {
  // ctx: { field, obstacles, rules, myId, rng() }
  // 闭包里的变量会跨 tick 保留（这就是你的"记忆"）。

  return {
    name: 'My First Tank', // 展示名（可选）

    onTick(view) {
      // view 是当前战场的只读快照（完全信息，双方互相可见）
      // 必须返回一个动作对象，四个字段都可选（缺省按 0/false 处理）
      return {
        throttle: 1,    // 1 前进 / -1 后退 / 0 不动（沿车体朝向移动 1 格）
        bodyTurn: 0,    // 车体转向：+1 顺时针 45° / -1 逆时针 45° / 0
        turretTurn: 0,  // 炮塔转向（独立于车体）：±1 转 45° / 0
        fire: false,    // true 朝炮塔当前方向开火（冷却中自动忽略，不算错误）
      };
    },
  };
};
```

把它存为 `my-tank.js`，然后用 CLI 验证和对战：

```bash
npm run arena -- validate my-tank.js          # 校验：加载检查 + 对靶机打 120 tick
npm run arena -- self my-tank.js              # 镜像测试：自己打自己
npm run arena -- play my-tank.js bots/sniper.js   # 挑战内置基准 bot
npm run arena -- serve replays/<最新的文件>.json  # 网页观看回放（支持逐帧、调速）
```

**强烈建议的开发循环**：`validate` → `self` → 挑战 `bots/` 里由弱到强的基准
（sitting-duck → random → chaser → sniper）→ 观看回放找问题 → 修改 → 重复。

## 1. 坐标系与方向

- 场地是 `W×H` 的格子（`ctx.field.width` / `ctx.field.height`，标准图为 32×24）。
- **x 向右增大，y 向下增大**（屏幕坐标习惯）。`(0,0)` 在左上角。
- 坦克朝向（车体 `dirBody`、炮塔 `dirTurret`）用 **0~7 的整数方向** 表示，每 +1 顺时针转 45°：

| dir | 名称 | (dx, dy) | dir | 名称 | (dx, dy) |
|-----|------|----------|-----|------|----------|
| 0 | N  | (0, -1)  | 4 | S  | (0, 1)   |
| 1 | NE | (1, -1)  | 5 | SW | (-1, 1)  |
| 2 | E  | (1, 0)   | 6 | W  | (-1, 0)  |
| 3 | SE | (1, 1)   | 7 | NW | (-1, -1) |

- 距离通常用**切比雪夫距离**（`max(|dx|, |dy|)`）思考——坦克八方向移动一格的代价相同。

## 2. 初始化：`createTank(ctx)`

引擎加载你的文件后调用一次工厂函数，返回包含 `onTick` 的对象。

`ctx` 字段（一次性给你，请存进闭包）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `field.width` / `field.height` | number | 场地尺寸 |
| `obstacles` | `[{x, y, w, h}]` | 障碍矩形列表（整格块，比赛中不变） |
| `rules` | object | 全部规则数值（见 §5） |
| `myId` | 0 或 1 | 你的坦克 id（出生位置由它决定，双方点对称） |
| `rng()` | () => number | **引擎提供的确定性随机数**，[0,1)。用它代替 Math.random |

## 3. 每 tick：`onTick(view)` → 动作

每个 tick 引擎同时向双方要一个动作，然后统一结算。**完全信息**：你和敌人的所有状态互相可见。

`view` 字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `tick` | number | 当前回合数（从 0 递增） |
| `field` | `{width, height}` | 场地尺寸 |
| `self` | Tank | 你的坦克 |
| `enemy` | Tank | 敌方坦克 |
| `bullets` | `Bullet[]` | 场上所有在飞的炮弹（双方的） |
| `rules` | object | 规则数值 |

`Tank` 字段：`id`、`name`、`x`、`y`、`hp`、`dirBody`、`dirTurret`、`cooldown`（剩余开火冷却）、`alive`、`violations`（累计违规次数）。

`Bullet` 字段：`x`、`y`（当前所在格）、`dir`（飞行方向）、`ownerId`（发射者）。

返回的**动作对象**：

| 字段 | 取值 | 说明 |
|------|------|------|
| `throttle` | -1 / 0 / 1 | 沿**车体**朝向前进 / 后退 1 格（0 不动） |
| `bodyTurn` | -1 / 0 / +1 | 车体转 45°（转向后**本 tick** 即按新朝向移动） |
| `turretTurn` | -1 / 0 / +1 | 炮塔独立转 45° |
| `fire` | boolean | 朝**炮塔当前方向**开火 |

- 四个维度**独立生效**，可以"边转车体、边转炮塔、边前进、边开火"。
- 越界的数值会被截断（如 `throttle: 5` → 1）；字段缺失按 0/false 处理。
- 返回非对象（null/数字/数组）计一次**违规**。

## 4. 结算顺序（极其重要）

同一 tick 内，引擎严格按以下顺序结算：

1. **冷却衰减**（所有坦克 cooldown 减 1，最低 0）
2. **转向**（车体、炮塔）
3. **移动**（按坦克 id 0→1 依次尝试；目标格出界/障碍/被坦克占用则原地不动）
4. **炮弹推进**（每颗炮弹沿方向走 2 个子步，**每个子步逐格检查**：撞墙/障碍消失，进入敌方坦克所在格则命中）
5. **开火**（cooldown ≤ 0 才生效；炮弹生成于坦克**本 tick 移动后**所在的格，下一 tick 才开始飞行）
6. **死亡清算**（HP ≤ 0 即死亡；双方同 tick 死亡为平局）
7. 回合数 +1；达到 `rules.maxTicks` 后按 HP 判定胜负

由此推出的**关键博弈事实**：

- **你的决策坐标 ≠ 你的发射坐标**。你基于移动前的 `view.self` 决策，但炮弹从移动后的位置射出。
  **移动中开火会系统性打偏**——要打准，先停下（throttle=0、bodyTurn=0），下一 tick 开火。
- **本 tick 移动可以躲炮弹**：炮弹在第 4 步才推进，而你第 3 步已经移动。看见炮弹相邻时侧移一格是有效的。
- **炮弹无视发射者**（可以穿过发射者），只命中敌方。
- 转向后立刻移动：想朝新方向走，转身的同一 tick 就可以配合 throttle。

## 5. 规则数值（`rules` 对象，标准值）

| 数值 | 标准值 | 说明 |
|------|--------|------|
| `maxHp` | 100 | 3 发炮弹击毁（34×3=102） |
| `bulletDamage` | 34 | 每次命中伤害 |
| `bulletSpeed` | 2 | 炮弹每 tick 前进 2 格（逐子步判定） |
| `fireCooldown` | 4 | 开火后需间隔 4 tick 才能再开 |
| `maxTicks` | 1500 | 回合上限，打满按 HP 判定（HP 相同平局） |
| `tickBudgetMs` | 30 | 每次 `onTick` 的响应时限 |
| `maxViolations` | 30 | 累计违规上限，达到即判负 |

**炮弹没有射程限制**——一直飞到撞墙/障碍/命中为止。

**命中模型**：炮弹只沿 8 方向直线飞行、逐格判定。因此**只有当敌方恰好处在你的八方向直线上
（`dx=0` 或 `dy=0` 或 `|dx|==|dy|`）且视线无障碍时，你才打得到它**。走位的核心就是
制造这种"直线关系"同时避免暴露在对方的直线上。

## 6. 沙盒限制

你的代码运行在受限 VM 中，**以下行为会导致报错（每次抛错计一次违规）**：

- ❌ `require` / `import`、文件系统、网络、`process`、`setTimeout` 等 —— 全部不存在
- ❌ `Math.random()` —— 已被替换为抛错；用 `ctx.rng()`（引擎保证确定性，可复现）
- ❌ `Date.now()` / `new Date()` —— Date 不存在
- ✅ 可用：`Math`（除 random）、`JSON`、`console.log`（收集进回放，帮你调试）、
  `Number/String/Array/Object/Map/Set/RegExp/Error` 等纯计算全局
- ⏱ **时间预算**：每次 `onTick` 超过 `tickBudgetMs`（30ms）计一次违规（该 tick 动作视为发呆）；
  累计 30 次违规判负。普通策略逻辑远用不到 30ms；避免无界循环。
- 💥 死循环会卡死沙盒 → 直接判负。

`console.log` 限额：每 tick 最多 5 行、每局最多 300 行，超出的丢弃。日志会写入回放，
在播放器里可以看到——用它来诊断"我为什么没开火"。

## 8. 常见陷阱（AI 请逐条自查）

1. **忘写 `module.exports = function createTank(ctx){...}`** ——导出的必须是工厂函数。
2. **`onTick` 返回了函数/类实例** ——只返回 `{throttle, bodyTurn, turretTurn, fire}` 普通对象。
3. **用 `Math.random()`** ——改用 `ctx.rng()`（要在 `createTank` 里先存下引用）。
4. **y 轴方向搞反** ——y 向下增大，北（N）是 `dy=-1`。
5. **移动中开火打偏** ——见 §4，站定射击。
6. **以为炮弹有射程/会转向** ——直线、无限远、逐格判定。
7. **忽略中央障碍挡视线** ——射击前检查路径上是否有障碍格（参考 bots/sniper.js 的 `pathClear`）。
8. **记忆不持久** ——`onTick` 里声明的局部变量每 tick 重置；跨 tick 状态放在 `createTank` 的闭包里。
9. **追击敌人时永远贴脸** ——距离太近时你也容易暴露在对方直线火力下；参考 bots/sniper.js 的距离管理。
10. **忽视对方炮口方向** ——`enemy.dirTurret` 指向你 + 你在对方直线上 = 马上要挨打，侧移脱离。

## 10. 判定胜负的方式

| 结束原因 | 胜者 |
|----------|------|
| 一方 HP ≤ 0 | 另一方（同 tick 双亡为平局） |
| 打满 `maxTicks` | HP 高的一方（HP 相同平局） |
| 一方违规 ≥ 30 次 | 另一方 |
| 一方沙盒崩溃/死循环 | 另一方 |

对局完全确定性：同代码 + 同种子 = 同结果。回放文件记录双方代码指纹（sha256），可复现验证。

## 11. Gameplay v2 开发者预览

Gameplay v2 继续使用同一个动作对象 `{throttle, bodyTurn, turretTurn, fire}`，但战场不再是同质坦克和
完全信息。它由 `src/core/v2/gameplay-engine.ts` 和 `src/runner/match-v2.ts` 真实运行，目前通过
TypeScript API 接入，CLI、网页控制台和播放器仍使用 v1。

### 11.1 三类车辆与武器

| 车辆 | HP | 正/侧/后装甲 | 极速 | 加速/减速 | 车体/炮塔转向 | 视野 | 武器 |
|---|---:|---:|---:|---:|---:|---:|---|
| 侦察 `scout` | 80 | 15/8/4 | 1000‰ | 500/750‰ | 1/1 tick | 10 | 轻型炮 |
| 中型 `medium` | 110 | 30/18/10 | 800‰ | 400/600‰ | 1/1 tick | 8 | 中型炮 |
| 重型 `heavy` | 150 | 55/32/18 | 600‰ | 250/400‰ | 2/2 tick | 7 | 重型炮 |

| 武器 | 伤害 | 穿深 | 射程 | 装填 | 弹速 | 弹药 |
|---|---:|---:|---:|---:|---:|---:|
| 轻型炮 `light-cannon` | 24 | 18 | 9 | 3 | 2 | 18 |
| 中型炮 `medium-cannon` | 34 | 26 | 10 | 4 | 2 | 14 |
| 重型炮 `heavy-cannon` | 48 | 40 | 11 | 6 | 2 | 10 |

速度和地形移动消耗都使用千分数累计，坐标仍保持整数。重型车不是“每 tick 固定慢走一格”，而是需要
更长时间加速并积累足够移动进度；松开油门或反向时按减速度制动。

### 11.2 地形、视野与装甲

- 开阔地：移动 1000‰、可见性 1000‰。
- 森林：移动 1100‰、目标可见性 700‰；不挡炮弹，但会降低别人发现你的距离。
- 泥地：移动 1600‰，明显拖慢进入该格的时间。
- 墙体：阻挡移动、视野和炮弹。

`view` 不再包含永远存在的 `enemy` 和全场 `bullets`，而是：

```js
{
  schemaVersion: 2,
  tick,
  field: { width, height },
  self,                 // 自己的完整状态，含 velocityPermille / ammunition 等
  visibleEnemies: [],   // 只包含当前看得见的敌人
  visibleProjectiles: [],
  objective             // 公开目标状态；歼灭模式为 null
}
```

发现条件为 `切比雪夫距离 × 1000 <= 自身视野 × 目标地形可见性`，且中间没有挡视野的墙。
失去视野后应由 Bot 闭包保存“最后已知位置”，不能假设敌人仍停在原地。

来弹方向会与目标车体朝向比较，判定正面、侧面或后方。实际伤害为：

```text
max(1, 火炮伤害 - max(0, 对应方向装甲 - 火炮穿深))
```

同一轻型炮命中重型车正/侧/后分别造成 1/10/24 点伤害，因此绕侧和保护车尾是实际规则，不是视觉设定。
弹药耗尽后开火会产生 `dry-fire` 事件；冷却期间开火仍被静默忽略；炮弹达到武器射程后消失。

### 11.3 v2 初始化上下文

`createTank(ctx)` 收到：`schemaVersion:2`、`teamId`、`field`、完整不可变 `terrainCells`、公开的
`captureZones`、所选
`vehicle`、`weapon`、`rules` 和确定性 `rng()`。地图是开局公开信息，敌方实时状态不是。

### 11.4 据点争夺

`capture` 模式除了歼灭对手，还可以通过占领地图中央目标获胜。单方在区域内连续停留 30 tick 即完成占领；
双方同时进入、占领方离开或被摧毁都会让连续进度归零。`view.objective` 会公开当前占领队伍、进度、目标值和
争夺状态，Bot 可结合 `ctx.captureZones` 规划路线。详细规则见
`docs/product/capture-mode-v2-spec.md`。

完整的机器规格见 `docs/product/gameplay-v2-vertical-slice-spec.md`。v2 比赛产物是自包含
MatchBundleV2，保存双方源码、内容/地图快照、实际动作、事件、权威状态检查点和日志，并可验证完整性。

## 12. 保存 Build 与历史版本练习赛

Gameplay v2 可以把“Bot 源码＋车辆装配”保存为 `SavedBuildV2`。同一个 `buildId` 下，每次真实内容变化
形成递增 revision，并用父指纹连接历史；相同内容重复保存不会创建无意义的新版本。

`runPracticeMatchV2` 可让当前 revision 对战任意旧 revision，也支持同 revision 镜像自测。Bot 本身仍只需
导出同一个 `createTank(ctx)` 工厂；版本管理发生在比赛外，不会给上场 Bot 增加文件或网络权限。每场练习赛
仍保存双方精确源码和装配到 MatchBundleV2，因此结果可回读、可复现、可验证。

该能力已接入桌面“我的车库”和“战术实验室”，首个版本也支持镜像练习；默认编辑保留自定义源码，
仅显式选择替换预设时改写策略。Ardot 历史基线位于 `2:115`（`3:299`、`3:399`、`3:492`）。
机器规格见 `docs/product/build-history-practice-spec.md`。

## 13. 0.1.1 / ruleset 2.1.0 兼容说明

桌面新比赛采用 ruleset 2.1.0；本文件第 1–10 节是 legacy v1，不能直接当作桌面规则。
2.1.0 同时结算移动：同目的地冲突、双方交换位置和进入回合开始时被占据的格子均阻止。
歼灭模式到时未分胜负则平局；据点模式到时有单方有效占领进度才判领先方获胜，否则平局。
历史 2.0.0 内容仍按旧移动与原始 HP 超时判定，原有版本/回放不会静默改写。

所有策略现由独立进程中的 QuickJS/WASM 执行，通过 JSON 传值，不暴露宿主对象。`ctx.rng()` 保持确定性，
真实时间、文件/网络与 Math.random 不可用。源码、日志、堆栈、内存和运行时间有限额；详见
[运行边界](engineering/runtime-security.md)。这不是 Windows 操作系统沙箱。
