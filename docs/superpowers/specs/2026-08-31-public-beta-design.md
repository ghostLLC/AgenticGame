# AgenticGame Public Beta 设计规格

日期：2026-08-31  
目标：先完成可公开下载、无需项目自建服务器的 B 版 Beta；通过全部验收门后，再启动 C 阶段商业化美术、音效、代码签名与发行工程。

## 1. 产品目标与非目标

B 版必须把当前“底层能力已经存在，但多数只能通过 API、CLI 或单一好友房间页面使用”的状态，收敛成普通玩家可以独立完成的桌面游戏闭环：首次启动、建立个人档案、选择或改进战术、保存版本、练习、邀请好友、观看回放、恢复中断、诊断问题和安装更新。

B 版是公开 Beta，不宣称商业发行完成。它必须功能完整、数据可靠、错误可理解、可生成安装包并具备真实双机验收流程；允许没有商业代码签名，允许视觉和音效尚未达到 C 阶段品质。

以下内容不属于 B 版：

- 恢复排位模式、账号体系、匹配、赛季和云端权威执行；`src/online` 继续封存。
- 项目自建信令服务或 TURN 服务。
- 100% 覆盖严格 NAT 网络；没有 TURN 时必须诚实提示连接边界。
- 商业级原创美术、完整动态音频、代码签名证书和商店上架。
- 重写确定性引擎、Replay v2、SavedBuild v2、Harness 或好友房间核心协议。

## 2. 已确认的产品约束

- 技术推进采用纵向切片，不做大爆炸重写。
- 保留 Electron + TypeScript；B 版不引入 React、Vue 或新的 UI 运行时。
- 默认界面必须是正常游戏界面，不是技术控制台。
- 无项目自建服务器：局域网一键发现优先；异地使用 WebRTC 邀请直连。
- 默认公共 STUN 可用于公网地址发现；不得暗中依赖 TURN。
- 极少数严格 NAT 网络可能无法异地直连，界面必须解释原因并提供诊断。
- 排位继续封存。
- Ardot 在 B 版开发期间不作为阻塞项；C 阶段恢复完整商业视觉流程。
- 每个纵切完成后同步 GitHub `main` 与飞书知识库，并生成可测试 Windows 产物。

## 3. 总体架构

### 3.1 主进程

Electron 主进程拥有文件系统、比赛沙盒、本地仓库、模型请求和恢复状态。新增 `DesktopApplicationServiceV1` 作为组合根，负责创建并持有以下边界清晰的服务：

- `PlayerProfileRepositoryV1`：昵称、首次启动进度和非敏感偏好。
- `SavedBuildRepositoryV2`：复用现有不可变 Build revision 仓库。
- `ReplayRepositoryV2`：复用现有完整性校验回放仓库。
- `PracticeMatchServiceV1`：把玩家选择转成现有 `runPracticeMatchV2` 调用并保存回放。
- `FriendRoomRecoveryStoreV1`：保存有时效的重启恢复胶囊。
- `AgentCenterServiceV1`：组合 Harness、provider 和多种子评测。
- `LanDiscoveryServiceV1`：只在玩家进入“附近好友”时启用局域网发现。
- `ReleaseDiagnosticsServiceV1`：检查数据目录、沙盒、网络、STUN、系统加密和版本。

### 3.2 Preload 与 IPC

渲染进程保持 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。Preload 只暴露版本化、用途明确的操作，不暴露任意路径、任意命令、任意网络请求或 Node API。

所有 IPC 输入在主进程重新校验。错误通过玩家错误码和安全文案返回；原始堆栈只写入本地诊断日志，不进入页面、回放、好友消息或 Agent transcript。

### 3.3 渲染进程

现有 `renderer.ts` 拆为小模块，但保持单一浏览器 bundle：

- `app-shell-v1.ts`：启动、导航和全局状态。
- `desktop-api-v1.ts`：窗口桥接类型与安全调用包装。
- `pages/onboarding-v1.ts`
- `pages/command-center-v1.ts`
- `pages/garage-v1.ts`
- `pages/practice-lab-v1.ts`
- `pages/friend-room-v1.ts`
- `pages/replay-library-v1.ts`
- `pages/agent-center-v1.ts`
- `pages/settings-v1.ts`
- `components/`：按钮、卡片、空状态、进度、确认对话框、错误提示和战术地图。

每个页面只依赖 `DesktopApiV1` 与自身 view model，不直接读取文件、启动 Worker 或调用 provider。

## 4. 本地数据与迁移

### 4.1 数据目录

新桌面版统一使用 Electron `app.getPath('userData')` 下的版本化目录：

```text
AgenticGame/
├─ profile/player-profile-v1.json
├─ settings/app-settings-v1.json
├─ builds/<buildId>/<revision>.json
├─ replays/<bundleHash>.json
├─ rooms/<sessionId>.room
├─ diagnostics/*.log
├─ quarantine/
└─ backups/
```

所有 JSON 通过临时文件、刷新和重命名原子写入。读取时严格校验版本和未知字段。损坏文件移动到 `quarantine` 并保留诊断记录，不静默覆盖或删除。

### 4.2 玩家档案

`PlayerProfileV1` 只保存：版本、玩家 ID、昵称、创建时间、最后启动时间、教程阶段、最近页面、最近 Build 标识和非敏感成就统计。玩家 ID 为本地随机 UUID，不用于账号或跨设备追踪。

`AppSettingsV1` 保存：语言、主音量、音效音量、动画强度、是否启用附近好友发现、默认联机模式、最近 provider 的非敏感配置和高级选项展开状态。

### 4.3 敏感状态

- API Key 只驻留内存；退出、provider 切换或玩家点击清除时立即丢弃。
- provider 厂商、Base URL 和模型名可以保存；请求 Header、密钥和敏感 transcript 不保存。
- 重启恢复胶囊默认 24 小时过期。
- Windows 上使用 Electron `safeStorage` 加密房间恢复胶囊。系统加密不可用时禁用重启恢复，不以明文降级。
- 恢复胶囊只用于重新建立同一逻辑房间，不能绕过双方重新在线或冒充另一座房间。

### 4.4 旧数据导入

首次启动检测旧的 `my-bots/`、`replays/` 和可识别的 v2 仓库。玩家明确确认后执行只复制导入；原目录不移动、不删除。重复内容按 Build fingerprint 或 bundle hash 去重。导入失败只影响单项，并生成可导出的报告。

## 5. 玩家流程

### 5.1 首次启动

1. 输入指挥官昵称。
2. 选择侦察、突击或堡垒入门战术。
3. 运行一场短教学战斗，依次解释移动、视野、方向装甲、弹药和据点。
4. 在回放中高亮最多三个关键时刻，解释胜负因果。
5. 返回指挥中心，解锁主要入口。

教程可跳过并可从设置重玩。教程进度在每个稳定步骤后保存；崩溃重启不会从头开始。

### 5.2 指挥中心

首页展示继续上次活动、快速练习、邀请好友、最近战报和当前战车。默认不出现源码、JSON、seed、tick、哈希、WebRTC、Offer、Answer、STUN、TURN 或 DataChannel。

### 5.3 车库与 Build 历史

玩家选择车辆、武器、装备和战术。保存会创建不可变 revision，不覆盖旧版本。历史时间线展示版本名称、配置差异、修改说明和战绩；源码、完整哈希和原始配置只在高级详情中显示。

损坏 revision 不可出战，但其他健康 revision 仍可使用。页面提供隔离、导出诊断和返回上一健康版本，不自动删除。

### 5.4 战术实验室

支持当前版本对战任意历史版本、同版本镜像训练、选择地图和模式。默认使用一个快速种子；高级评测允许 3、5 或 10 个种子。比赛复用真实 Gameplay v2 沙盒，结果保存为 Replay v2，并可一键打开回放。

### 5.5 回放库

回放卡片展示日期、模式、参赛 Build、胜负、时长和完整性状态。支持按日期、结果、模式和 Build 筛选；支持备注、打开、导出和确认后删除。删除移动到应用回收区，保留七天后才清理；玩家可在设置中立即清空回收区。

好友房间公开回放与本机完整 Replay v2 分开标识。客人端不会因为保存公开回放而获得对方源码、原始动作或调试日志。

### 5.6 页面失败状态

每个页面必须覆盖加载、空数据、损坏数据、运行中、可取消、失败和成功状态。玩家只看到可行动的原因和下一步；原始异常堆栈进入本地诊断日志。

## 6. 好友联机与恢复

### 6.1 两条配对路径

**附近好友**：进入页面后临时启用局域网 UDP 广播/监听。邀请包含随机 nonce、会话 ID、应用协议版本和显示名，不包含 Bot 源码。玩家点击对方卡片后仍通过现有 WebRTC/DataChannel 和房主权威会话开赛。离开页面立即停止广播。

**异地好友**：保留 AGFR2 压缩邀请和确认流程，改成分步游戏卡片、剪贴板自动识别和明确进度。二维码只编码同一邀请内容，是可选辅助，不引入服务器或短码服务。

### 6.2 NAT 边界

默认使用公共 STUN 发现公网候选；不包含 TURN 凭证。连接超时后诊断页区分：邀请版本错误、双方未同时在线、ICE 超时、严格 NAT 可能性和本地防火墙阻止。文案明确说明没有中继时部分网络无法直连。

### 6.3 应用重启恢复

恢复胶囊保存角色、sessionId、公开快照、自己的已验证 Build、恢复 revision、到期时间和必要的加密会话状态。重启后首页显示“继续好友房间”。

恢复仍要求双方重新在线并建立新的 WebRTC 连接。客人必须重新发送自己的已验证 Build；房主恢复权威状态并比较 sessionId/revision。已完成比赛的公开回放独立保存，不依赖恢复成功。过期、篡改或无法解密的胶囊被拒绝并提供新建房间入口。

### 6.4 房主退出与过期

房主是比赛权威。房主明确退出会向客人发送房间关闭事件；意外退出只进入可恢复状态。B 版不做房主迁移。恢复胶囊到期后房间结束，但已保存 Build 和回放不受影响。

## 7. Agent Center

### 7.1 玩家流程

1. 选择现有 Build 或新建战术。
2. 选择厂商预设或自定义 OpenAI-compatible 端点。
3. 输入 API Key；页面明确提示仅本次运行使用。
4. 用玩家语言描述目标，例如“更积极抢点，但不要侧面对敌”。
5. Harness 在受限工具白名单中读取规则、生成候选并运行真实评测。
6. 展示多种子胜率、平均剩余 HP、违规、超时和关键时刻。
7. 玩家确认后才保存为新 revision；取消不改变当前 Build。

### 7.2 Provider

- 继续支持 OpenAI-compatible Chat Completions。
- 新增 Anthropic Messages 原生适配器，但厂商类型不渗透进 Harness 或游戏工具层。
- provider 请求统一支持 AbortSignal、超时、响应大小限制、错误脱敏和 localhost 伪装域名防护。
- 自定义端点默认只允许 HTTPS；显式 loopback 可用于本地模型。

### 7.3 多种子评测

快速评测 3 个 seed，标准评测 5 个，深入评测 10 个。每个候选使用同一组固定 seed 对阵基准 Build，汇总胜率、平局率、HP、违规和运行时错误。玩家可以取消剩余比赛；已完成结果保留在本次会话摘要中，但未确认的候选不写入 Build 仓库。

## 8. 教程、可访问性与音频基线

B 版提供最小但完整的声音反馈：按钮、准备、开赛、命中、摧毁、胜利、失败和断线。使用仓库可分发或程序生成的占位资产，并保留独立音量控制；不把它描述为商业级音效。

键盘可以完成导航、确认、返回、时间轴控制和主要表单操作。焦点可见，文本对比度满足桌面可读性，动画强度可降低。窗口最小尺寸仍为 1100×700，并在 1440×900 完成主验收。

## 9. 发布、诊断与更新边界

### 9.1 Windows 产物

B 版同时生成：

- 可移植 ZIP，用于直接解压测试。
- 未签名 NSIS 安装包，安装到当前用户目录并提供卸载入口。

安装和卸载默认不删除玩家数据。彻底删除数据必须由玩家在卸载确认或设置页明确选择。未签名安装包可能触发 Windows SmartScreen，发布说明必须如实提示。

### 9.2 诊断

设置页可以运行：数据仓库完整性、比赛沙盒、系统加密、剪贴板、局域网发现、STUN 连通性和版本检查。导出诊断包前显示包含内容；诊断包排除 API Key、Bot 源码、完整邀请卡和房间恢复密文。

### 9.3 更新

B 版不内置静默自动更新。应用可打开 GitHub Releases 页面并比较非敏感版本号；下载和安装由玩家确认。C 阶段再决定签名更新通道。

## 10. 安全与隐私

- 好友房间是互信模式；房主设备会执行客人的策略源码。界面在首次好友对战前明确提示一次。
- 客人只接收公开战报和公开回放，不接收房主源码、哈希、原始动作或调试日志。
- 所有持久化契约有版本、大小上限和严格字段校验。
- 所有好友消息有方向、sessionId、revision 和大小校验。
- Bot 继续在当前 Worker/VM 沙盒中执行；B 版公开说明其不是面向恶意不可信代码的强隔离。C 或正式排位前必须升级到进程级或 WASM 隔离。
- 诊断、日志、Agent transcript、飞书和 Git 提交不得包含密钥或恢复内容。

## 11. 纵向切片与依赖顺序

### Slice 1：桌面平台、档案与首次启动

建立 ApplicationService、严格本地仓库、IPC、模块化 App Shell、指挥中心和可恢复首次教程。它为所有后续页面提供数据和导航边界。

### Slice 2：车库、Build 历史与战术实验室

接入现有 SavedBuild 仓库、装配内容、revision 时间线、镜像练习和新旧版本练习；结果保存到 Replay 仓库。

### Slice 3：回放库与统一播放器

接入 Replay v2 列表、筛选、完整性、备注、导出和回收区；复用战术地图组件显示本地完整回放与好友公开回放。

### Slice 4：局域网发现与应用重启恢复

新增附近好友发现、异地邀请流程优化、诊断、加密恢复胶囊、房主退出和房间到期。

### Slice 5：Agent Center

接入内置 BYOK UI、Anthropic 原生 provider、取消、脱敏、多种子评测和确认保存 revision。

### Slice 6：Beta 发布与验收

完成设置、音频基线、诊断导出、旧数据导入、NSIS 安装包、发布说明、真实双机验收脚本和最终回归。

每个 Slice 必须独立通过测试、类型检查、桌面构建、界面走查和 Windows 候选包启动；不能把质量问题累计到 Slice 6。

## 12. 测试策略

所有行为变更使用测试驱动开发：先写失败测试并确认因缺失能力失败，再实现最小代码使其通过。

- 纯契约：严格 JSON、迁移、损坏隔离、到期和敏感字段测试。
- 服务：真实临时目录、原子写入、Build/Replay/Practice/Agent 组合测试。
- IPC：允许列表、输入校验、错误映射和渲染层无 Node 权限测试。
- UI：控制器/view model 单元测试、静态玩家文案测试、Playwright 主流程与截图。
- 联机：内存 Peer、真实双标签 WebRTC、局域网 discovery 回环、重启恢复和失败诊断测试。
- 发布：资源清单、安装/卸载策略、可移植目录、EXE 启动响应和 ZIP hash。
- 安全：API Key、源码、邀请、恢复胶囊和诊断包泄漏回归。

## 13. B 版完成门

B 版只有同时满足以下条件才称为达标：

1. 新用户无需命令行即可完成教程、保存 Build、练习、看回放和邀请好友。
2. Build 历史、新旧版本练习和 Replay Studio 已进入玩家桌面界面。
3. 附近好友可以发现；异地邀请流程可用；严格 NAT 失败有明确诊断。
4. 应用重启后可在 24 小时内重新会合原房间；过期和篡改安全失败。
5. Agent Center 支持 OpenAI-compatible 与 Anthropic 原生 BYOK，密钥不持久化。
6. 多种子评测只在玩家确认后创建新 revision。
7. 可移植 ZIP 与未签名 NSIS 安装包均能在干净 Windows 用户环境启动。
8. 两台真实 Windows 设备完成局域网和异地邀请验收；无法覆盖的 NAT 类型被记录而不是隐瞒。
9. 自动化测试、类型检查、依赖审计、桌面构建和打包全部通过。
10. GitHub `main`、飞书知识库、README、HANDOFF 和发布说明与候选包一致。

达到这些门后冻结 B 版功能，只修复阻断缺陷；随后为 C 阶段另写商业视觉、音频、签名、安全沙盒和商店发行规格。
